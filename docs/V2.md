# Central JP2auto V2 — piloto local

## Executar no Windows

Requisitos: Node 22.13+ e pnpm (o projeto declara pnpm 11.25.0).

Abra o terminal na pasta deste repositório e execute:

```powershell
pnpm.cmd install
pnpm.cmd dev
```

Abra o endereço `Local` informado, normalmente http://localhost:3000. Mantenha o terminal aberto. Não são necessários Corepack, Sites, Cloudflare ou login de desenvolvimento para iniciar o painel.

## Primeiro uso

1. Configure empresa, dias úteis e horários em Configurações.
2. Cadastre os colaboradores e seus setores em Equipe.
3. Ajuste os limites de espera em SLAs e alertas.
4. Cadastre um atendimento com cliente, assunto, origem e setor. Código Bling, Nº OS e protocolo Digisac são opcionais.
5. Abra a tratativa para registrar observações, editar, transferir, pausar por pendência do cliente ou finalizar.
6. Consulte os indicadores e exporte um backup JSON antes de atualizar ou trocar de navegador.

## Dados e regras

- O Bling será o cadastro oficial. Código de cliente, Nº OS e protocolo Digisac são campos diferentes; não há vinculação automática por nome ou telefone.
- O Trello acompanha o andamento; finalização técnica não equivale a entrega concluída.
- Cada atendimento recebe um identificador local JP2. Tratativas por telefone, presencial ou representante podem não ter protocolo Digisac.
- Finalização preserva o registro e seu histórico. Exige motivo. Pode ser reaberta por edição.
- O limite desta versão mede espera útil acumulada; não é ainda uma métrica de primeira resposta nem prazo de resolução por etapa.
- Aguardando empresa, em atendimento e pendente interno contam espera. Aguardando cliente pausa. Observações não reiniciam o relógio.
- O calendário usa o fuso do computador e horas inteiras. Feriados e intervalos de almoço não estão configurados neste piloto.
- Próximo acompanhamento continua gerando pendência mesmo quando o cliente deve agir.
- Alterações de limites valem para novos registros. Alterar calendário recalcula a parcela ativa da espera.
- Indicadores usam todos os registros que correspondem aos filtros. Avaliações são inseridas manualmente e exibem o tamanho da amostra; não representam análise automática de qualidade.

## Limites desta entrega

Dados persistem apenas no localStorage deste navegador. Use uma aba por vez. Não há autenticação, autorização por perfil, banco compartilhado ou monitoramento em segundo plano. Não publique para uso real com dados de clientes antes de implementar esses recursos.

Não há integração ativa ou envio de notificações. A tela Integrações armazena somente URLs de referência, nunca credenciais. O acesso do assistente ao Trello/GitHub não fornece autorização ao aplicativo hospedado.

Não copiamos os dados demonstrativos da V1 para indicadores reais. O armazenamento antigo `jp2auto-tickets` permanece intacto. Para registros reais cadastrados na V1, mantenha a cópia anterior e solicite uma migração revisada.

O backup JSON inclui dados de clientes. Armazene em local restrito; nunca envie ao repositório público. Restaurar substitui os dados V2 somente após validação e confirmação.
